# 04 驱动层、中间件与链接脚本详细说明

本章覆盖自定义 `driver/`、`middleware/`，以及与业务相关的 `cmd/` 链接脚本要点。  
**不包含** TI `include/`、`source/` 外设库源码解释。

---

## 4.1 `sys_ctrl_cpu2` — CPU2 最小系统初始化

### 为何独立于 `InitSysCtrl`

双核应用中，**PLL/时钟主配置由 CPU1 完成**。CPU2 只需：

1. 关看门狗  
2. Flash 构建：拷贝 `.TI.ramfunc` 到运行区并初始化 Flash wait  
3. 打开本核用到的外设时钟（当前仅 Timer0/1/2）

### `void SysCtrlCpu2_Init(void)`

```text
DisableDog()
#ifdef _FLASH
  memcpy(RamfuncsRunStart, RamfuncsLoadStart, RamfuncsLoadSize)
  InitFlash()
#endif
打开 CPUTIMER0/1/2 时钟
```

### `SysCtrlCpu2_InitPeripheralClocks`（静态）

`EALLOW` 下置位 `PCLKCR0` 的三个 CPU Timer 时钟使能位。

## 4.2 `dual_core_cpu2` — 双核握手与 GS 保护

### IPC 标志定义

| 宏 | 值 | 含义 |
|----|-----|------|
| `IPC_DUAL_FLAG_CPU1_READY` | `0x10` | CPU1 就绪 |
| `IPC_DUAL_FLAG_CPU2_READY` | `0x20` | CPU2 就绪 |
| `IPC_DUAL_FLAG_CPU1_EVENT` | `0x1` | CPU1 触发周期事件（采样完成） |
| `IPC_DUAL_GS_CPU2_MASK` | `0x17` | CPU2 等待的 GS master 掩码 |
| `IPC_DUAL_HANDSHAKE_TIMEOUT_MS` | `3000` | 握手超时 |

### `void DualCore_WaitGsRamMaster(void)`

忙等：`GSxMSEL & MASK == MASK`，确保相关 GS RAM 归属正确后再继续。

### `void DualCore_ConfigGsRamAccessProtect(void)`

- GS3 / GS4：**允许 CPU 写**（`CPUWRPROT=0`）  
- GS3 / GS4：**禁止 DMA 写**（`DMAWRPROT=1`）  

防止 DMA 意外改写共享业务数据。

### `DualCore_Cpu2Status_t DualCore_HandshakeCpu2(uint32_t timeoutMs)`

1. 轮询等待 CPU1 ready 标志，超时返回 `DUAL_CORE_ERR_CPU1_NOT_READY`  
2. ACK CPU1 ready  
3. `DualCore_WaitGsRamMaster()`  
4. 置位 CPU2 ready  
5. 返回 `DUAL_CORE_OK`

`main` 在非 OK 时死循环。

## 4.3 `interrupt` — IPC0 中断框架

### 设计

采用**回调注册**，把底层中断向量与应用服务函数解耦：

```text
RegisterCpuIntCallback(&CpuIntServiceFun)
Interrupt_Init()  → PIEVect.IPC0_INT = CPU_Interrupt
```

### `interrupt void CPU_Interrupt(void)`

1. 若回调非空则调用  
2. `ClearCpuInterrupt()`：ACK `IPC_DUAL_FLAG_CPU1_EVENT` + `PIEACK_GROUP1`

### `void Interrupt_Init(void)`

- 映射 `PieVectTable.IPC0_INT`  
- 使能 PIE Group1 INTx13（IPC0）  
- `IER |= M_INT1`  
- 若启动时 EVENT 已忙，先 ACK 清一次  

**注释明确：故意不使能 CLA。**

## 4.4 `cpu_timers` — 系统节拍与 ISR 测时

### 定时器分工

| 定时器 | 配置 | 用途 |
|--------|------|------|
| Timer0 | 1 s 周期中断 | 仅自增 `InterruptCount`（预留） |
| Timer1 | 见下文 | **ISR 负载测时**（自由运行读 TIM） |
| Timer2 | 1 ms 周期中断 | 系统时间基，`InterruptCount` 作 ms 计数 |

### 关于 `EN_CLA_RUN_TIME_MEASURE`

头文件定义为：

```c
#define EN_CLA_RUN_TIME_MEASURE (0)
```

C 预处理器 `#ifdef EN_CLA_RUN_TIME_MEASURE` 判断的是**宏是否定义**，与数值无关。因此当前工程中该分支为**真**：

- Timer1 配置为超长周期自由运行（`PRD=0xFFFFFFFF` 风格）  
- `TCR` 不以“周期中断使能”方式启动（`0x0000`）  
- **不注册/不使用**常规 `cpu_timer1_isr` 体  

`CpuIntServiceFun` 通过读 `CpuTimer1Regs.TIM` 计算 ISR 忙/闲时间。

### 软定时状态机 `TimerState_t`

`CpuTimerFlag()` 在 main 中轮询：当距上次记录 ≥1 ms 时，累加各档计数并置位：

- 1 / 5 / 10 / 20 / 100 / 500 / 1000 ms 标志  

`Get_xx_Flag()` 读标志；`Timers_xx()` 清标志。  
当前 `main` 仅实质性使用 **1 ms**（FlagUpdate），其余档位预留。

### 时间差工具

- `TimGetSystime()`：返回 Timer2 中断计数  
- `TimDifftime` / `TimDifftimeFromNow`：处理 32 位回绕的差值计算

## 4.6 `middleware/mid_filter` — Butterworth 低通

### 一阶（工程实际使用）

双线性变换：

\[
y_n = a_0 x_n + a_1 x_{n-1} - b_1 y_{n-1}
\]

其中 \(w_t = 2\pi f_c / f_s\)，

\[
a_0 = a_1 = \frac{w_t}{w_t+2},\quad
b_1 = \frac{w_t-2}{w_t+2}
\]

**使用处**：`MidVolAndRcmuRms` 对漏电流滤波（`fc=500 Hz`，`fs=20 kHz`）。  
`Update` 放在 `.TI.ramfunc`。

### 二阶（已实现、当前无调用方）

ζ = 0.707，系数设计与历史 CLA 实现一致。API：`Init/Reset/Update` 齐全，供后续复用。

## 4.7 链接脚本要点（`cmd/`）

### `2837xD_FLASH_lnk_cpu2.cmd`（业务相关）

| 区域 / Section | 用途 |
|----------------|------|
| BEGIN `0x080000` | CPU2 入口 |
| PROGRAM_SECTOR | 应用 Flash |
| `.TI.ramfunc` LOAD Flash → RUN **RAMD1** | ISR/算法热路径 |
| `.stack` → RAMD0 | 栈（约 2KB） |
| `.ebss` → GS0–2 | 普通全局变量 |
| `ramgs0` → GS3 | 双核共享（偏 CPU1 ADC） |
| `ramgs1` → GS4 | CPU2 电量接口 / STS 输出 |
| CPU2TOCPU1RAM / CPU1TOCPU2RAM | IPC 消息区 |
| Cla1Prog → LS0–4；CLA 数据 → LS5 | CLA 预留 |

### `F2837xD_Headers_nonBIOS_cpu2.cmd`

TI 标准外设寄存器内存映射；与业务逻辑弱相关，附录收录以便完整对照工程配置。

## 4.8 驱动 / 中间件与应用的衔接

```
SysCtrlCpu2_Init          →  main 最先调用
DualCore_HandshakeCpu2    →  共享区可用前置条件
DualCore_ConfigGsRam...   →  GS3/4 写保护策略
Interrupt_Init            →  IPC0 → CpuIntServiceFun
CpuTimer_Init             →  1ms 软定时 + ISR 测时
Mid_Filter1OrderButter_*  →  漏电流 LPF
SysRestart                →  未接线预留
```
