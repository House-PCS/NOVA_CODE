# 04 应用层：通信与协议

对应源码：`protocol_process`、`ethernet_analysis`、`modbus_analysis`、`private_analysis`、`debug_analysis`

---

## 1. `protocol_process` — 通信总调度

### 1.1 初始化顺序

`MidComserviceInit` → `PrivateParamInit` → `FirmwareParamInit` → `ModbusRegInit` → `NetworkInit` → `UploadInfoInit`

### 1.2 `ProtocolProcess()` 每主循环

1. `EthernetProcess()`  
2. `MidComserviceHandle()`（串口帧拼包）  
3. `ModbusProcess()`  
4. `SystemFirmwareUpdate()`  
5. 从 `gstSciRevQueue` 取一帧  
6. 按类型分派：Modbus 主/从、私有读写请求/响应  

状态枚举 `EN_PROTOCOL_STATUS`：IDLE、Modbus host/slave、私有读写请求/响应。  
当前私有「读请求/读响应」分支基本为空骨架。

## 2. `ethernet_analysis` — UDP 监控协议

### 2.1 网络参数

- IP：`192.168.1.9`  
- UDP 端口：`2001`  
- 芯片：CH390（SPI）

### 2.2 寄存器映射

| 区 | 地址范围 | 含义 |
|----|----------|------|
| PCS 输入（上传） | `0x6000~0x621F` | 实时状态/功率等 |
| PCS 持有（控制） | `0x6220~0x631F` | 配置与命令 |
| ARC | `0x6400~0x647F` | 电弧板镜像 |
| Copro | `0x6480~0x64FF` | 协处理器镜像 |

### 2.3 关键结构

- `MonitorUdp_t`：命令、32 位地址、长度、负载  
- `NetworkInfo_t`：MAC/IP/UDP、收包状态  
- `UdpPCSPara_t gstUdpPcsPara`：上传区 + 持有区 + ARC/Copro  

### 2.4 `EthernetProcess()` 流程

1. 超时复位管理（约 10 s 无通信可重启 CH390，最多 3 次）  
2. 查 CH390 中断/收包  
3. 链路变化更新 LED  
4. ARP 请求 → 回 ARP  
5. 本机 UDP 2001 → 解析监控协议  
6. `MonitorDataUpload()` 刷新上传区  
7. `_MonitorAnalysis()` 处理读写并可回复  
8. 调试端口 `0x08FC` → `DebugReveiveAnalysis()`

### 2.5 `_MonitorAnalysis()` 命令

| 命令 | 行为 |
|------|------|
| `0x43` | 按地址读 PCS/ARC/Copro 上传或持有 |
| `0x45` | 写持有寄存器；地址落在 `0x24600000~0x248FFFFF` 时转固件升级接收 |

写持有寄存器会映射到：工作模式、电池/PV/电网/油机功率、SOC、CT、电表、并网标准、开关、DRM、保护点、校准系数等。

### 2.6 其它接口

- `GetEthSysUpgradeState()`：升级中标志  
- `InvSwitchStateGet()`：充/放任一非零且未远程关机  
- `BackupSwitchStateGet()`：备电使能连续 500 次后为真  
- `Ch390SendMonitor()`：手工组以太网/IP/UDP 回包  

### 2.7 风险提示

- UDP/IP 校验和可为 0（依赖网络容忍）  
- 监控写直接改控制对象，缺少完整范围校验/原子提交/认证  
- 长度主要截断到约 1100，末尾边界校验需结合具体解析路径确认

## 3. `modbus_analysis` — Modbus RTU 主从一体

### 3.1 角色

- **从机**：对外提供与 UDP 寄存器区一致的 03/04/06/10  
- **主机**：轮询 ARC / Copro / 电表  

### 3.2 关键对象

- `gstModBusPara`：ARC/Copro 镜像与通信统计  
- `garrReadDealFram[4]`：四类轮询定义  
- `gstModbusSendQueue`：深度 3 的主动写队列  
- `gstMeterInfo`：电表三相电流/功率  

### 3.3 主机 `ModbusProcess()`

1. 升级期间暂停普通轮询  
2. 优先处理主动写队列  
3. 否则约每 350 ms 轮询 ARC/Copro 四项  
4. 等待 ACK 或 350 ms 超时  

`ModbusHostRead`：组 03/04 帧发送。  
`ModBusHostWrite10`：组 0x10 写多寄存器。  

**严重缺陷**：`ModBusHostWrite10()` 中存在 `uint8_t *p = NULL` 后立即写 `p[0]...` 的路径，一旦执行会空指针写——量产前必须修复。

### 3.4 从机 `ModbusCmdAnalysis()`

完整 RTU 状态机，功能码：

- 04 输入寄存器 → `udp_pcs_upload`  
- 03 保持寄存器 → `udp_pcs_hold`  
- 06 / 10 写保持 → 直接写 `udp_pcs_hold`  

`ModbusRTUSend`：追加 CRC 经 SCI 发送。

### 3.5 写控制辅助

`WriteArcHoldReg`、`SetArcSysReset`、`SetCoproSysReset`：入队写 ARC/Copro。

## 4. `private_analysis` — SCI 私有协议（升级转发）

### 4.1 帧格式要点

- 请求头 `0x5A`，响应头 `0xA5`  
- 升级命令：`0x80F0` start、`0x80F1` busy、`0x80FF` end  

### 4.2 发送口映射

`PrivateDataSend`：COM0→SCIB，COM1→SCIC，COM2→SCIA。

### 4.3 `_CmdAnalysis()`（升级写路径）

1. **start**：初始化 DSP 固件写地址与校验  
2. **busy**：识别序号、校验 DSP 类型、写 SPI Flash、累加 checksum  
3. **end**：比对 checksum，写升级标志页  

`PrivateUpgradeRunning()`：私有升级活动后保持约 5 s 忙状态，供 Modbus 暂停轮询。

---

## 5. `debug_analysis` — 调试通道

### 5.1 能力

- `DEBUG_CPU_CHANNEL_NUM = 96`  
- `SetCpuDebugData(ch, float)`：带越界检查写入  
- `ScidSendMessage()`：发 CLA 16 路 + CPU 96 路  
- `Debug_Send()`：组播/定向 UDP（源 `192.168.1.18` → `192.168.1.16:1000`）  
- `DebugReveiveAnalysis()`：写入 `gDebugValue[10]`  

### 5.2 风险

`DebugReveiveAnalysis` 按传入 `len` 写 10 元数组，**未限制长度**，存在越界风险。

static void _EthernetRestartProcess(void)
{
    static uint32_t timeout = 0;
    static uint32_t ethernet_timeout_count = 0;
    static uint16_t restart_count = 0;
    static uint16_t sta = 0;
    static uint16_t restart_status = 0;

    if(sta == 0)
    {
        if(TimDifftimeFromNow(timeout) > 1000)
        {
            if(_gstNetworkInfo.recv_network_state == 1)
            {
                LedCtlSucceed(LED_SRC_SYS);
                _gstNetworkInfo.recv_network_state = 0xFF;
                ethernet_timeout_count = 0;
            }
            else if(_gstNetworkInfo.recv_network_state == 2)
            {
                LedCtlBlink(LED_SRC_SYS, RUN_LED_BRINK_PRIED);
                _gstNetworkInfo.recv_network_state = 0xFF;
                ethernet_timeout_count = 0;
            }
            else
            {
                ethernet_timeout_count++;
            }

            /* ��ʱ10Sû��ͨ�� ��ิλ3��*/
            if(ethernet_timeout_count > 10)
            {
                if(restart_count < 3)
                {
                    CH390RestartEnable();
                    ethernet_timeout_count = 0;
                    /* ��һ��״̬ */
                    sta = 1;
                }
            }

            timeout = TimGetSystime();
        }
